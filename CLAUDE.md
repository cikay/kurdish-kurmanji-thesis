# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Install dependencies: `pipenv install --dev` (see [README](README.md#installation)).

MinerU **is** in the Pipfile (`mineru==4.0.10`) and `extract.py` imports it. On arm64 macOS
the base package pulls `mineru[torch]` itself, so there is no extra to pick. It used to run
as a subprocess from its own virtualenv, because MinerU 3's `transformers` pinned
`huggingface-hub` below 1.0; MinerU 4 wants `transformers>=5.10.1`, which does not, so the
pin here is back to `1.17.0`. See [README Installation](README.md#mineru) for what running
it in-process gave up: the per-document timeout, and a killed worker no longer being a child
process.

**The version pin is load-bearing for the file format, not just reproducibility.** MinerU 3
returned `pdf_info` → `para_blocks` → `lines` → `spans` and a `_middle.json` on disk; 4.0
returns objects, `pages` → `blocks` → `content`, and no file. Downgrading would need
`extract.py` rewritten back.

Running the pipeline: see [README Usage](README.md#usage). Each stage script can also be run
directly, bypassing `pipeline.py` — its `__main__` block hardcodes real `data/<stage>` paths,
e.g. `python sections.py` reads `data/extract` and writes `data/sections`. The knobs still
come from `config.yml` (`stage_config`), so a direct run and a pipeline run cannot tune
differently — including `extract.only_theses`, which is what stops a ~45-hour MinerU pass
from starting because someone ran `python extract.py`.

Tests (pytest, no package structure — `tests/conftest.py` puts the repo root on
`sys.path`):
```bash
pipenv run pytest
pipenv run pytest tests/test_sections.py
pipenv run pytest tests/test_sections.py::TestText::test_headings_and_prose_both_become_text
```

A `pdb.set_trace()` left in the code stops every test that reaches it. To run the suite with
one in place, switch it off in memory. `-p no:debugging` is required: without it pytest's own
debugger plugin puts `pdb.set_trace` back.
```bash
PYTHONBREAKPOINT=0 pipenv run python -c "
import pdb, sys; pdb.set_trace = lambda *a, **k: None
import pytest; sys.exit(pytest.main(['-q', '-p', 'no:debugging']))"
```

No linter/formatter is configured in this repo.

## Architecture

Five-stage pipeline — `download → extract → sections → stats → filter` — orchestrated by
`pipeline.py`; inputs and outputs are in [README.md](README.md#pipeline-stages).

The dataset serves **two training uses at once**: continued pre-training (CPT) on the `text`
column, and supervised fine-tuning (SFT) on the summary columns — summarizing `text` into a
given language, and translating one summary into another. Both uses read the same rows, which
is why the summaries are taken out of `text` — though a summary the thesis prints a second
time is no longer removed (see `sections.py` below).

- **Stage contract** (`stage.py`): every stage is a `Stage` subclass with a `name` and
  `run(input_dir, output_dir)`. `pipeline.py` builds each stage from `REGISTRY` (name →
  class), derives `input_dir`/`output_dir` purely from stage order in `config.yml`
  (`data/<stage_name>/`), and forwards any extra `config.yml` keys for a stage as constructor
  kwargs — see [README's "Adding a stage"](README.md#adding-a-stage).
- **Manifest handoff**: each stage reads `manifest.jsonl` from its input dir and writes its
  own to its output dir. A stage that drops a record simply omits it — there's no
  tombstoning. Only `extract` *whitelists* the fields it forwards (its input is the download
  manifest, and `pdf_file` has no business downstream); every later stage spreads
  (`{**record, ...}`). `extract` writes `blocks_file` and no `.txt`; `sections` reads the blocks file and adds
  `txt_file`. `stats` counts words in that `.txt`.
- **`data/` is gitignored** in full. Outputs are regenerated by running the pipeline. The
  exception is `tests/data/`, tracked as test fixtures.
- **`extract.py` runs MinerU** in-process (`mineru.parse`) and writes `data/extract/<tez_id>.blocks.json`
  — a JSON list of blocks in reading order, `[{"text", "type", "page"}, ...]`. `blocks.py` owns that file format and the `BlockType` enum both halves share:
  `BlockType`, `Block`, `dump`, `load`, `toc_entries`, `normalize_nfc`, `line_text`.
  - `mineru.parse(path, tier=, ocr_mode=, image_analysis=False)` returns a `ParseResult`
    whose `.pages` are `docvortex` models — MinerU's own document schema, a separate
    package. There is no output directory, no `_middle.json` and nothing to parse back, so
    this module has no schema classes of its own: it reads `page.page_idx`, `page.blocks`,
    `block.type` and `block.content` directly. Importing `docvortex` is pydantic only and
    costs 0.08s, which is why the tests build real blocks instead of dictionaries.
  - `BLOCK_TYPES` maps MinerU's types to the four this project writes. Both title types
    become `TITLE` — MinerU calls a heading `doc_title` or `paragraph_title` and is not
    consistent about which (`532507`: `ÖZET` is a `doc_title`, `KURTE` a `paragraph_title`,
    two pages apart), and the `level` comes from the same judgement, so neither is read.
    `ref_text` (a bibliography line) stays `text`, so `sections.py` keeps deciding what a
    bibliography is by its `ÇAVKANÎ` heading — one measured rule rather than two that can
    disagree. **Everything absent from the map is dropped, and that now includes the page
    furniture**: MinerU 3 kept `page_number`, `header`, `footer`, `aside_text` and
    `page_footnote` in a separate `discarded_blocks`, and 4.0 returns them among the blocks.
  - There is no `abstract` type any more — 4.0 returns a summary page's body as `text`.
    `BlockType.ABSTRACT` is kept in `blocks.py` only so a file written before the upgrade
    still loads.
  - Every string passes through `MinerUExtractor._text` — `normalize_nfc` then `line_text`
    — so NFC is done once, at the boundary. It used to be a stage of its own. `_text` joins
    a block's spans with nothing between them (a span is a piece of a line, and a style
    change can fall inside a word) and nested blocks with a space (a list's items, a
    contents page's entries, each its own line). The hyphen-healing `line_text` once did
    fired 77 times against the corpus, all false positives.
  - **The contents page becomes `index` blocks, one per entry, never joined.** Joined, the
    entries weld into `KURTE .... III ÖZET .... IIV`: 14 of 24 sampled theses were parseable
    that way, against 19 of 22 kept apart. In 4.0 the entries come from nesting rather than
    from lines — a contents page is one `index` block whose `content` is a block per printed
    line (`KURTE.. ...Ⅱ`, `1.2.1.Pêşdaçek.. 9`) — and `_entries` reads them. So in the file,
    `type == index` means "a line of the contents page, as `extract` decided": a heading
    MinerU mislabelled can be one, and an `index` block MinerU put in the body is not.
    `toc_entries` returns their text in order.
  - **`_contents_positions` decides which blocks are the contents page by position, never by
    text** — `BEŞA YEKEM` is a contents entry and also the real chapter heading later on.
    Each rule was measured over six fully extracted theses:
    - An `index` block past the first quarter (`CONTENTS_REGION = 0.25`) is body text
      MinerU mislabelled, and becomes text. Real contents blocks ended by page 14; false ones
      started at page 61 — a poem in `447830` (493 words), a story list in `465880`, a
      plagiarism report in `532507`. Before this rule all of it was lost into the toc.
    - A single block between two contents blocks is a contents entry MinerU mislabelled,
      whatever type it gave it — the gap is the signal, not the type. Every one in the
      sample was a heading: `BEŞA YEKEM`–`BEŞA ÇAREM` (`447830`), `LÎSTEYA ŞEKLAN` and
      `LÎSTEYA WÊNEYAN` (`1003999`), `LÎSTEYA TABLO Û ŞIKLAN` (`887531`). Only one block:
      `1003999` has 28 blocks — its summaries — between its contents and its list of
      figures.
    - **The contents page's own title is not handled.** MinerU 4 usually puts it inside
      the `index` block, as its first entry: `443619` gives `NAVEROK`, `443622`
      `NAVEROK......... I`, `388894` `NAVEROK . VI`. Where it does not (`532507` returns a
      separate `paragraph_title`), the word stays a heading in `text` — one word out of
      16.4 million. The code that moved it, `get_content_title` and `_is_contents_title`,
      is in `attic/contents_title.py` with its tests in `attic/contents_title_tests.py`,
      which also hold the `CONTENTS_TITLE_RE` and `normalize_heading` they need.
    - Known gap: an image between two contents blocks breaks the one-block rule.
  - **This replaced PyMuPDF, and the trade is real in both directions** — the numbers are in
    [README](README.md#extraction-what-mineru-buys-and-what-it-costs). It rescues theses
    whose text layer is unreadable (scanned front matter; broken font cmaps, which 42 of 417
    theses show) and loses summaries on theses whose contents page was readable, by merging
    `KURTE` into the title block above it. On a 22-thesis sample: 54 summaries against the
    old pipeline's 33, with 6 of the old ones lost.
  - **It is slow, and 4.0 is not faster.** Measured end to end on `532507` (94 scanned
    pages, so every page OCRed): 4.0.10 tier `basic` 323s, 3.4.5 318s — 0.29 pages/sec
    both. The 0.64 pages/sec a 10-page probe showed was front matter, which is lighter than
    body pages; do not quote it. The corpus is 73,604 pages, most with a readable text
    layer, so a full pass is 45–70 hours. `extract.only_theses` keeps one from starting by
    accident.
  - **Tier, not backend.** 4.0 replaced `backend`/`method` with `tier` (`flash`, `basic`,
    `standard`, `advanced`) and `ocr_mode`. `basic` is the layout-plus-OCR path and the
    nearest thing to 3.x's `pipeline`. `standard` and `advanced` load a local vision model —
    llama.cpp Qwen-VL, two minutes before the first page — which this corpus cannot afford.
  - **It runs out of memory at its own defaults.** MinerU reads a document in windows of
    pages, default 64; on 16GB a document needing more than one window kills a worker and the
    run ends with an *empty* error and a leaked-semaphore warning. `532507` (94 pages) fails
    at 64 and succeeds at 16. `_apply_window_size` sets `MINERU_PROCESSING_WINDOW_SIZE` from
    `extract.processing_window_size` (16) before each call — `backend/analysis/pdf/window.py`
    reads that variable when the analysis starts, not at import, so setting it in-process is
    in time.
    Now that MinerU runs here, that killed worker is inside the pipeline process.
  - **The window size changes the output.** Two runs at 16 were byte-identical; a run at 8
    changed 120 of 1015 blocks (OCR punctuation, Turkish `ı`/`i`). Treat it like a model
    version and pin it.
  - A result with no pages is a failure, not only an exception: MinerU used to exit 0 on a
    failed document (`862523` failed inside a batch with an empty error and succeeded alone),
    and in-process it can log a failure and return normally just the same. `_parse` checks
    `result.pages` and catches any exception, reporting the document either way, so one bad
    PDF does not end a 417-thesis pass.
  - **MinerU spawns worker processes**, so anything that drives this stage has to be an
    importable file with a `__main__` guard — `python extract.py` is fine, `python -c` and a
    heredoc are not (the workers re-import `__main__` and fail on `<stdin>`).
  - `_parse_options` passes `image_analysis=False`: every image, table and chart block is
    dropped, so describing them is work for output nothing reads. 4.0 writes no files unless
    asked, so there is nothing else to turn off.
  - Earlier attempts are recoverable from history rather than re-litigated: PyMuPDF plus the
    contents page is the branch `contents-driven-sections` (commit `2196edc`, no longer
    in this branch's history); the Docling branch is `structured-extraction`.
- **`toc.py` is deleted**, with `tests/test_toc.py`. Nothing imported it once
  `get_content_title` left `extract.py`. It is on the branch `contents-driven-sections` — commit
  `2196edc` is the last one that used it — and that is the fallback if the MinerU switch is ever reverted.
  Its `CONTENTS_TITLE_RE` and `normalize_heading` are copied into
  `attic/contents_title.py`. What it measured: `CONTENTS_TITLE_RE` names
  `NAVEROK` (355 theses), `ICINDEKILER` (6), `TABLE OF CONTENTS` (2), `CONTENTS` (1) and the
  Zazaki `TEDEYI` (25, once as `TEDEYÎ (NAVEROK)` in `383854`); `FIHRIST` was dropped because
  no thesis uses it. `TocParser` found a contents page by leader dots (4 or more); on MinerU
  output it found only 2 of 5 sampled contents styles (`KURTE.iv`, `KURTEI` and
  `2. KURTEIII` have too few dots). Its 1041-of-1064 result was on PyMuPDF text.
- **`sections.py` produces the dataset columns.** `ThesisReader.sections` walks the blocks,
  skips the contents page's `index` blocks, and cuts the rest into `Section`s at headings; `_create_section` gives each a `SectionKind`
  (`TEXT`, `SUMMARY`, `BIBLIOGRAPHY`) read off its heading. The walk only cuts — what each
  kind becomes is decided afterwards, over the finished list.
  - **`SUMMARY_OPENINGS` matches the opening word only**, because MinerU merges the thesis
    title and author into the heading (`KURTE DAÇEK DI ZARAVAYÊ KURMANCÎYÊ DA Bahattin
    TAMAN`). The `\b` is load-bearing: without it `KURTE` matches `KURTEBÊJE` and
    `KURTEPEYV`, the abbreviations lists, printed by 14 of 22 sampled theses.
  - **`_is_title_page_furniture`**: a heading that arrives while the open summary has fewer
    than `summary_min_words_before_heading` (50) words is dropped — it is the thesis title or author,
    which MinerU marks as headings. Measured: furniture headings arrived with 0–2 words in
    the summary, real boundaries with 143 or more. Its cost: an abstract under 50 words would
    swallow the next section (none in the sample). Title-page *text* blocks are kept in the
    summary on purpose — 4 of 54 sampled summaries start with them, 53 words in all (`887531`
    `eng_summary` starts `Master Thesis`). They are easy to drop when aligning parallel data,
    but they stay in the SFT targets.
  - **`_first_summary_section`**: the first summary per language wins. `610994` prints 15 `KURTE`
    headings — its abstract, then a `Kurte` of each story it analyses. Untaken summary
    sections stay in `text` (`_paragraphs`), so none of that is lost.
  - `_summary_text` cuts each summary where `KEYWORDS_RE` first matches (45 of 54 sampled
    summaries have keywords). The cut is at the label, not at the block, so keywords MinerU
    merged into the abstract's last block go and the prose before them stays (`931752`).
    The label needs its colon, unless it is a whole block — MinerU can put the colon, or
    the keywords themselves, in the next block (`751831`: `Key Words`, then
    `: Migration, ...`). Measured on a full run: 38 of 1151 summaries changed, every cut a
    keywords list or the page furniture after it. `874610` lost 411 words — its Turkish
    abstract, which followed an unknown label (`Miftepeyvên Sereke`) into `kmr_summary`.
  - **`BIBLIOGRAPHY_RE`** — `ÇAVKANÎ` plus at most one more word — drops the section. Cost:
    `4.Çavkanî` in `546095` is 224 words of prose about sources. The real signal, that a
    bibliography sits at the end, is not used.
  - **Language is judged twice, each over a finished piece, never per block.**
    `sections.py` calls `langid.detect_lang` (GlotLID) directly — it is not
    passed in — and `langid.py` imports `fasttext` only when the model is first used, so
    importing `sections.py` stays free.
    - **A section is dropped from `text` when its label is not in `SECTION_LANGUAGES`**
      — the labels of Kurmanji, Zazaki and Sorani in `LANGUAGE_LABELS`: `kmr_Latn`,
      `kiu_Latn`, `diq_Latn`, `ckb_Arab`, `hac_Arab`, `sdh_Arab` (`_is_lang_valid`, called
      from `_paragraphs`).
      A section is its heading and the blocks under it, so the blocks before the first
      heading are one too, and so is a second `ÖZET`. A section under
      `min_words_for_lang_detect` (50; it was 20 when the numbers below were measured,
      and at 50 the drop in the Kurmanji theses is about 242,000 words) is kept unjudged.
      No score.
    - **All three languages are let through here on purpose.** Measured on 61,656 sections: inside the
      407 Kurmanji theses GlotLID labels 319,217 words of sections `kiu_Latn` or
      `diq_Latn`, and the sampled ones were not Zazaki — Kurmanji title pages and headings
      in capitals (`3. SÎNEMAYA KURDÎ Û BÎRA KOLEKTÎF`, `kiu_Latn` 1.00), glossaries,
      reference lists under `Pirtûk` or `Kitêb`, Sorani in Latin letters. Keeping only
      `kmr_Latn` was tried: it dropped 579,554 words there. With Zazaki kept it drops
      260,337 (18,763,980 → 18,503,643): 207,617 Turkish, 9,866 English, about 43,000
      under noise labels — `KURTEBÊJE` comes back `frp_Latn` or `bew_Latn`. Under 10 words
      83% of sections are labelled something other than Kurmanji (76% under 20), which is
      what the word knob is for.
    - **`filter.py` says which language a thesis is in**, with one `detect_lang` call
      over its `.txt`, looked up in `filter.text_langs` (`FilterStage.judge`), and writes
      it as `text_lang`. Over a whole thesis the label is reliable: before any section was
      dropped, 407 of 457 were `kmr_Latn` and the lowest score was 0.77 (`612291`). Now:
      447 kept — 408 `kmr_Latn` (18,574,237 words), 29 `zza_Latn` (1,162,986), 4
      `ckb_Arab` (105,254), 6 `hac_Arab` (250,276) — and 10 dropped
      (`min_words_for_lang_detect: 50`, `min_word_count: 1000`).
    - **Zazaki is one language, `zza_Latn`.** GlotLID has two labels for it and does not
      split the theses between them reliably: of 29 Zazaki theses, 5 get one label for the
      whole text and the other for most of their paragraphs.
    - **Sorani is `ckb_Arab` alone at thesis level**, though `hac_Arab` and `sdh_Arab`
      count as Sorani for a section or a summary (`878001`, clean Unicode Sorani, is 47%
      `ckb_Arab` and 48% `hac_Arab` by section). The reason: thirteen more Arabic-script
      theses are printed in old fonts and extract damaged, and `hac_Arab`, `knc_Arab`,
      `arz_Arab` are what GlotLID calls that. Some are Sorani, some Kurmanji (Badini,
      `482021`); none is readable. The four kept: `878001`, `825820`, `531485`, `502253`.
    - **`hac_Arab` is a subset of its own, added by the user, and it is damaged text.**
      `filter.text_langs` has `hac_Arab: hac_Arab`, so the six theses whose whole text
      gets that label are kept under it: `917623`, `517144`, `737293`, `473610`,
      `473612`, `484015`. The code means Gurani; the theses are Sorani and Kurmanji in
      old fonts, with the letters mapped wrong (`ثەسچبٚ دەکەٚێذ`). All six were sampled
      and none reads as text. They have no Sorani summary — `پوختە` does not survive
      the damage — but five have Turkish and English ones. Do not merge the subset into
      `ckb_Arab`. The other seven damaged theses are dropped: six too short after the
      section check, one `arz_Arab`.
    - **One thesis is filed wrong.** `458722` is in `kmr_Latn` and is Sorani in Latin
      letters: whole, it was `kiu_Latn` at 0.58; with its damaged Arabic-script sections
      dropped, the 51,759 words left are `kmr_Latn` at 0.61.
    - **`min_word_count` is 1000 because of fragments.** At 100, `482021` and `447746`
      were kept in `zza_Latn` with 134 and 225 words — the short sections left of two
      damaged Arabic-script theses. The shortest real thesis has 7,076 words.
    - **A summary not in the language its heading claims becomes `null`**
      (checked inside `_summary_text`, logged at INFO). 11 of 1151: shifted columns
      (`751821`: Turkish under `KURTE`, English under `ÖZET`; `874610`, `476000`,
      `846697`), things that are not summaries (`906430` keywords, `502779` a list of
      tables, `531485`, `519361`), and a Zazaki abstract (`375244`). The detector never
      *moves* a summary to another column — that would recover about 5 and lets two
      sections compete for one column. The rejected section does not go back into `text`,
      and if the contents page names it, it is in `unrecovered_summaries`.
    - What this leaves in: a foreign passage inside a Kurmanji section. The per-section
      check that used to run here dropped 3,036,603 words corpus-wide.
  - **Nothing drops a reprinted summary.** `RestatementFilter`, which dropped body
    paragraphs that reprint a summary (n-gram overlap, `duplicate_*` knobs), was removed.
    A thesis that reprints its abstract in the foreword keeps that copy in `text`, so the
    SFT target can sit inside the CPT input.
  - `_promised_missing` searches each contents entry (`toc_entries`) for a summary word. A language
    the contents page names with no column to show for it goes to `unrecovered_summaries` —
    otherwise a scanned abstract and one the thesis never had are the same `null`. `447830`
    and `887531`, the two theses MinerU costs, report `['kmr_Latn', 'tur_Latn']`.
  - Writes `data/sections/<tez_id>.txt` and a manifest row adding `paragraph_count`,
    `unrecovered_summaries` and `summaries` — one dict keyed by `SUMMARY_LANGUAGES`
    (`kmr_Latn`, `zza_Latn`, `ckb_Arab`, `tur_Latn`, `eng_Latn`), `null` where there is
    none. It replaced the `kmr_summary`, `tur_summary`, `eng_summary` columns. Zazaki
    headings: `KILMNUS` (11 of 30 theses), `KILMVATE` (4), `KILMÎYE` (2) — not
    `KILMNUŞTEYÎ`, their abbreviations list. Sorani: `پوختە`. 21 Zazaki and 4 Sorani
    summaries are found. There is no
    `.sections.json` any more.
  - `SectionsStage.__init__` takes `**config_kwargs` straight into `SectionsConfig`, so a new
    knob is one dataclass field and one `config.yml` line.
- **`download.py`** scrapes `tez.yok.gov.tr` with `requests`/`BeautifulSoup` in a multi-step
  flow: POST a search form (`TezSearcher`), GET the results page, then per thesis resolve a
  one-time download key and stream the PDF (`PdfDownloader`). TLS verification is
  deliberately disabled (`verify=False`, warnings suppressed) and browser-like headers are
  hardcoded — both are load-bearing for the site to respond; the target language is
  hardcoded as `Dil=11` (Kurdish).
- **`modal_extract.py`** is not a `Stage` either — a standalone Modal app that runs the
  extract stage one thesis per container (`MAX_CONTAINERS = 40`), because nothing is shared
  between theses. Commands are in [README](README.md#running-extract-on-modal).
  - It calls `ExtractStage.extract_one` and `ExtractStage.selected`, which `run` also
    calls, so there is one extract path. `manifest_row` builds a row from the blocks alone;
    that is how a thesis already on the volume is skipped without running MinerU again.
  - The knobs come from `config.yml`, copied into the image when the run starts.
    `only_theses` is the only way to choose theses, so a full pass still needs it emptied.
  - The volume `kurmanji-thesis` is mounted at `/root/data` and the code runs in `/root`,
    so the manifests' relative paths (`data/download/532507.pdf`) need no rewriting.
  - The image pins the versions the Mac resolved to, and sets
    `MINERU_MODEL_SMALL_BACKEND=torch`: MinerU's `auto` picks onnx models on a bare CPU and
    torch ones on a GPU, and the Mac (MPS) runs torch. On Linux `mineru` does not pull
    torch by itself; the `torch` extra does.
  - **Measured on a T4, 8 cores.** `532507` (94 scanned pages): 70s end to end against the
    Mac's 323s, MinerU's own log 1.87 pages/sec for inference. `1003999` (164 pages, 153
    with a text layer): 74s, 2.93 pages/sec for inference. About 18s of each run is outside
    inference. Two theses; a CPU container was not timed.
  - **Why the script and not a shell.** `python extract.py` runs unchanged in a
    `modal shell` container and was tried: it works, but reads one thesis after another,
    7 to 9 hours for the corpus.
  - **The Mac's GPU is not why the Mac is slow or fast**: MinerU picks `mps` there, but 16
    pages took 30s on MPS and 28s with `MINERU_DEVICE_MODE=cpu`.
  - **The blocks differ from the Mac's.** `532507`: 1159 blocks both, 1031 identical, 128
    changed in OCR details (a full stop, `İmza`/`imza`) — the size of the window-size
    difference. One change is structural: `NAVEROK` came back a `title` on Modal and an
    `index` on the Mac. Do not mix the two sets of files.
  - Modal gives back what in-process MinerU lost: `TIMEOUT_SECONDS` ends a hung document,
    and a killed worker ends one container, retried once.
  - Not covered by tests, like `_parse`: check a change by running it with one thesis in
    `only_theses`.
- **`push_to_hub.py`** is not a `Stage` — a standalone CLI that reads
  `data/filter/manifest.jsonl` and pushes one subset per `text_lang` (`kmr_Latn`,
  `zza_Latn`, `ckb_Arab`, `hac_Arab`; `config_name` in `push_to_hub`), each with `tez_id`, `title`,
  `url`, `word_count`, `text` and `summaries`. Requires `HF_TOKEN` in `.env`; refuses to
  push if the target repo already exists. It does not upload `dataset_card.md`; that is done by hand
  after the push. The card describes the current design, and its `configs` block names
  the four subsets, so it can replace the README the push generates. **Its numbers are
  from one run** (447 theses) and go stale when the data changes. `build_datasets` was
  run locally; the push itself was not.

## Testing conventions

Tests call a stage's collaborators directly rather than round-tripping through files:
`MinerUExtractor._blocks(pages)` with real `docvortex` blocks (`block()`, `pages()` in
`tests/test_extract.py`), `ThesisReader(...).read([...blocks])` and
`SectionsStage.read_thesis(...)` in `tests/test_sections.py`, `FilterStage.judge(record)`
in `tests/test_filter.py`. Follow this pattern.

GlotLID is never loaded by the tests either. `tests/test_filter.py` patches
`filter.detect_lang`, and the autouse fixture `no_glotlid` in
`tests/test_sections.py` replaces `sections.detect_lang` with `fake_detect_lang`: a text is
Turkish, English, Zazaki or Sorani by which of the fixture words `turkce`, `english`,
`zazaki` and `sorani` it has most of, and Kurmanji otherwise.

The extract fixtures build MinerU's own models rather than dictionaries, which is why they
are worth the care they need: a block's `index` must be its reading-order position, a nested
image or table body must carry its parent's index, and a `paragraph_title`'s `level` starts
at 2. A fixture the real parser could not produce fails to build — which is the point.

The suite runs offline and in well under a second — keep it that way.

**MinerU is never run by the tests.** It loads models and reads under a page a second.
`_parse` is not covered — importing `mineru` is free but calling it is not — so
`_parse_options` and `_apply_window_size` are tested instead, and a change to `_parse` has
to be checked by running the stage against a real PDF via `extract.only_theses`.

Contents-region fixtures need body blocks behind them — `FILLER` in `tests/test_extract.py` —
because the region is the first quarter of a thesis's blocks.
